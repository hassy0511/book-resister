# 本の貸出管理アプリ 要件定義書

- 最終更新: 2026-11-08
- ステータス: 確定

---

## 1. 背景と目的

- 図書館・マンションの図書室・学校・保育園など、本を借りる場所が複数あり、**どの本をどこで借りて、いつまでに返すか**が分からなくなる。これを一元管理する。
- 過去に借りた本、特に**シリーズもののどの巻を読んだか**が分からなくなる。これを履歴で管理して解消する。
- 家族で同じデータ（貸出中の本、返却日、履歴）を共有する。

## 2. 前提・制約

| 項目 | 内容 |
|---|---|
| 利用端末 | iPhone（iOS 16.4 以上）が中心。PC 向けの最適化はしない（表示はできる） |
| 費用 | **完全無料**。有料プランやクレジットカードの登録が必要なサービスは使わない |
| 利用者 | 家族（数名） |
| 言語 | 日本語 |

## 3. 用語

| 用語 | 意味 |
|---|---|
| グループ | 家族単位の共有範囲。グループ内のデータはメンバー全員が見られる |
| メンバー | グループに参加してログインする人。「借りた人」はメンバーから選ぶ（借りる人を別に管理はしない） |
| 場所 | 本を借りる施設（図書館、図書室、学校、保育園など）。利用者が自分で登録する |
| 本 | 書誌情報（タイトル、著者、ISBN など） |
| 貸出 | 1 冊の本を 1 回借りた記録。返却すると履歴になる |

## 4. 機能要件（初回リリース）

### 4.1 アカウント・家族グループ

| ID | 要件 |
|---|---|
| F-01 | Google アカウントでログインできる。Google アカウントを持っていない家族は、メールアドレスとパスワードでも登録できる |
| F-02 | 初回ログイン時に、グループを新しく作るか、招待リンクから既存のグループに参加する |
| F-03 | メンバーはグループへの招待リンクを発行できる |
| F-04 | メンバーは表示名を設定できる（「借りた人」として表示される） |
| F-05 | グループ内のデータはメンバー全員が閲覧・編集できる（権限の差は設けない） |
| F-06 | 1 人が所属するグループは 1 つとする |
| F-07 | 招待リンクを誤って家族以外に送ったときに備え、メンバーは「これまでの招待リンクをすべて無効にする」ことと、他のメンバーをグループから外すことができる（F-05 のとおり権限の差は設けない。外すと、これまでの招待リンクもすべて無効になる） |

### 4.2 借りる場所の管理

| ID | 要件 |
|---|---|
| F-10 | 場所を登録・編集できる。項目は「名前」「既定の貸出期間（日数）」「メモ（任意）」 |
| F-11 | 履歴がある場所は削除せず、非表示にできる（過去の履歴は残す） |
| F-12 | 貸出冊数の上限は管理しない（場所側で管理しているため） |

### 4.3 本を借りる（登録）

| ID | 要件 |
|---|---|
| F-20 | カメラでバーコードを読み取り、ISBN（978／979 で始まるもの）を取得する。2 段目のバーコード（192 で始まる価格コード）は無視する |
| F-21 | **連続スキャンモード**：複数冊を続けて読み取り、最後に「場所」「借りた人」「借りた日」「返却日」をまとめて設定して登録する |
| F-22 | ISBN からタイトル・著者・出版社・表紙画像を自動で取得する |
| F-23 | 書誌情報が見つからない本や、ISBN がない本（月刊絵本、古い本、図書館のシールでバーコードが隠れた本など）は、**タイトル検索**または**手入力**で登録できる |
| F-24 | 「借りた人」の既定値は操作している本人。他のメンバーに変更できる |
| F-25 | 「借りた日」の既定値は今日 |
| F-26 | 「返却日」は「借りた日 ＋ 場所の既定貸出期間」で自動計算する。1 冊ごとに修正できる |
| F-27 | 登録するときに、その本を過去に借りたことがあれば表示する |
| F-28 | 同じ本がすでに貸出中なら警告する |

### 4.4 貸出中の一覧（ホーム）

| ID | 要件 |
|---|---|
| F-30 | 貸出中の本を返却日が近い順に一覧表示する |
| F-31 | 場所ごと・借りた人ごとに絞り込める |
| F-32 | 返却日を過ぎた本、返却日まで 3 日以内の本を色分けして目立たせる |
| F-33 | 一覧の上部に「期限切れ ○冊／3 日以内 ○冊」のような要約を表示する |

### 4.5 延長

| ID | 要件 |
|---|---|
| F-40 | 貸出中の本の返却日を変更できる（延長に対応する） |

### 4.6 返却

| ID | 要件 |
|---|---|
| F-50 | 1 冊ずつ返却できる |
| F-51 | **場所単位でまとめて返却**できる（例：「○○図書館の分を全部返却」）。その中の一部だけを外すこともできる |
| F-52 | 返却時に読書状況を選ぶ。選択肢は「読んだ」「途中まで」「読んでいない」で、**既定値は「読んだ」** |
| F-53 | 返却日の既定値は今日 |
| F-54 | 誤って返却した場合に取り消せる |

### 4.7 履歴

| ID | 要件 |
|---|---|
| F-60 | 返却済みのものも含めて、すべての貸出記録を見られる |
| F-61 | タイトル・著者で検索できる |
| F-62 | 場所・借りた人・期間で絞り込める |
| F-63 | 本ごとに、借りた回数と、いつ・どこで・誰が借りたか、読書状況を表示する |

### 4.8 シリーズ管理

| ID | 要件 |
|---|---|
| F-70 | 本に「シリーズ名」と「巻数」を持たせる |
| F-71 | シリーズ名と巻数はタイトルなどから自動で推定し、手で修正できる |
| F-72 | シリーズ画面では、巻ごとに「読んだ」「途中まで」「読んでいない」「まだ借りていない」を表示する |
| F-73 | シリーズの全巻数を任意で入力できる。入力されていれば、まだ借りていない巻を表示する |
| F-74 | 全巻数が分からない場合は、借りたことのある巻を巻数順に並べ、抜けている巻番号を表示する |

### 4.9 スキャンで確認（既読チェック）

| ID | 要件 |
|---|---|
| F-80 | 書店や図書館の棚でバーコードを読み取るだけで、その本を借りたことがあるかを確認できる（登録はしない） |
| F-81 | 借りたことがあれば、いつ・どこで・誰が借りたかと読書状況を表示する |
| F-82 | シリーズの本であれば、そのシリーズの既読状況も表示する |
| F-83 | 確認画面からそのまま「借りる」登録に進める |

### 4.10 感想・評価

| ID | 要件 |
|---|---|
| F-90 | 貸出記録ごとに、評価（★1〜5）と感想（自由記述）を任意で入力できる |
| F-91 | 返却時に入力できる（任意）。後から追加・編集もできる |
| F-92 | 本の詳細画面で、家族全員の評価と感想をまとめて見られる |

### 4.11 返却日の通知

| ID | 要件 |
|---|---|
| F-100 | 返却日の **3 日前**と**前日**に、**グループのメンバー全員**にプッシュ通知を送る |
| F-101 | 通知は毎朝 8 時ごろに 1 回送る（仕組み上、数十分ずれることがある） |
| F-102 | 同じ日に返却日を迎える本が複数ある場合は 1 通にまとめる（例：「明日返却：○○図書館 3 冊、△△保育園 1 冊」） |
| F-103 | 返却日を過ぎても返却されていない本は、返却されるまで毎朝通知する |
| F-104 | 返却済みの本については通知しない |
| F-105 | 通知を受け取るには、端末ごとに「ホーム画面に追加」と通知の許可が必要。アプリ内で手順を案内する |

## 5. 非機能要件

| 項目 | 内容 |
|---|---|
| アプリの形態 | PWA（Web アプリを iPhone のホーム画面に追加して使う形）。App Store では配布しない |
| 同期 | 家族の誰かが操作した内容が、数秒以内に他の端末にも反映される |
| セキュリティ | グループ外の人はデータを読んだり書いたりできない |
| 想定規模 | メンバー 6 人程度、貸出記録は年間 1,000 件程度。無料枠に十分収まる |
| オフライン | 電波が弱い場所でも、直近のデータは閲覧できるとよい（任意） |
| 操作性 | 片手で操作できること。よく使う操作（スキャン、返却）は 2 タップ以内で開始できる |

## 6. 技術方針（案）

| 領域 | 採用予定 | 備考 |
|---|---|---|
| フロントエンド | PWA（React + TypeScript + Vite を想定） | 実装開始時に確定する |
| ログイン | Firebase Authentication | Google ログインとメール＋パスワード |
| データベース | Cloud Firestore | リアルタイム同期とオフラインキャッシュ |
| ホスティング | Firebase Hosting | |
| 定期通知 | GitHub Actions の定期実行（毎朝）＋ Web Push | 下記「無料で収めるための注意」を参照 |
| バーコード読み取り | ZXing 系の JavaScript ライブラリ | iPhone の Safari で動作するもの |
| 書誌情報 | 国立国会図書館サーチ API、openBD、Google Books API | 取得できる情報と優先順位は実装時に検証する |

### 無料で収めるための注意

- Firebase は無料の **Spark プラン**で運用する。Cloud Functions と Cloud Storage は従量課金の Blaze プラン（クレジットカードの登録が必須）が必要なため、使わない。
  - 定期通知は Cloud Functions の代わりに **GitHub Actions** で毎朝実行する。非公開リポジトリでも無料枠（月 2,000 分）に収まる（1 日 1 回、1 分未満の見込み）。
  - 公開リポジトリでは、60 日間更新がないと定期実行が自動で止まるため、**リポジトリは非公開にしておく**。
  - 表紙画像は書誌 API の画像 URL を参照するだけで、アプリ側には保存しない。手入力した本は表紙なし（既定の画像を表示）とする。
- 「Apple でサインイン」は Apple Developer Program（有料）が必要なため使わない。

## 7. データ構造（概要）

すべてのデータはグループの配下に置き、グループのメンバーだけがアクセスできるようにする。

| データ | 主な項目 |
|---|---|
| グループ | 名前、招待コード |
| メンバー | ユーザー ID、表示名、所属グループ |
| 場所 | 名前、既定の貸出期間（日数）、メモ、非表示フラグ |
| 本 | ISBN（ない場合あり）、タイトル、著者、出版社、表紙画像 URL、シリーズ、巻数 |
| シリーズ | 名前、全巻数（任意） |
| 貸出 | 本、場所、借りた人、借りた日、返却日、返却した日、読書状況（読んだ／途中まで／読んでいない）、評価、感想 |
| 通知の登録情報 | メンバー、端末ごとのプッシュ通知の宛先 |

## 8. 画面構成（案）

画面下部のタブで「ホーム」「スキャン」「履歴」「シリーズ」「設定」を切り替える。

| 画面 | 内容 |
|---|---|
| ログイン／グループ作成・参加 | 初回のみ表示 |
| ホーム | 貸出中の一覧、期限が近い本の要約、返却ボタン |
| スキャン | 「借りる」と「確認」のモードを切り替える。連続スキャンに対応 |
| 借りる内容の確認 | 読み取った本の一覧と、場所・借りた人・日付の一括設定 |
| 返却 | 場所単位の一括返却、読書状況・感想の入力 |
| 本の詳細 | 書誌情報、貸出履歴、家族の感想、シリーズへのリンク |
| 履歴 | 検索と絞り込み |
| シリーズ一覧／シリーズ詳細 | 巻ごとの既読状況 |
| 設定 | 場所の管理、メンバーと招待、通知、表示名 |

## 9. 今回の対象外

### 今後のリリースで対応する

- 読みたい本リスト（次に借りたい本）
- CSV／Google スプレッドシートへの出力
- 読んだ冊数の集計

### 対応しない

- 場所ごと・人ごとの貸出上限の管理
- 図書館のシステムとの自動連携（貸出状況の自動取り込み）
- ログインしない家族（子どもなど）を「借りた人」として別に管理すること
- PC 向けの画面最適化
- App Store での配布
- 手持ちの本（買った本）の管理
- 図書館で予約中の本の管理

## 10. 決定事項（旧・未確定事項）

| # | 内容 | 決定 |
|---|---|---|
| 1 | 手持ちの本（買った本、家にある本）の登録 | 対象外 |
| 2 | 図書館で予約中の本の管理 | 対象外 |
| 3 | 読んだ冊数の集計（人ごと・年ごとなど） | 次のリリース以降に検討 |
| 4 | 返却日を過ぎた本の通知 | 延滞している間は毎朝通知する（F-103） |
| 5 | 通知の時刻 | 毎朝 8 時ごろ（F-101） |

## 11. 利用開始までの準備（実装時に案内する）

1. Firebase のプロジェクトを作成する（Google アカウントでログインするだけ。クレジットカードは不要）
2. GitHub のリポジトリに、通知の送信に使う鍵を登録する（Secrets）
3. 家族の iPhone で、アプリをホーム画面に追加して通知を許可する
